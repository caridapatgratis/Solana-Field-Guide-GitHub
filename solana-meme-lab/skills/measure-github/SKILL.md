# Measure two different GitHub questions
**Input:** A preregistered venue/date window, a complete or documented random sample of new mints, as-of repo evidence and buyer events. Do not select from trending lists, winners, repo search or only graduated tokens.

1. **Own-project referral share.** Use a distinct link from the repo to the site/demo, and optionally ask first-time buyers where they heard about the coin. With informed consent, attribute a unique first purchase to a referral. Publish `observed GitHub-referred first buyers / all first buyers in the same period`, the counts, coverage and how attribution was measured. In a survey also report `GitHub answers / respondents`, response rate, unknown and multiple-source answers. Clicks and GitHub stars are not buyers. Never deanonymize visitors or link social handles to wallets without consent. No attribution for unknown bot traffic.
2. **Market association.** Freeze the evidence window at creation +2 min. From time-stamped sources assign `none`, `link-only`, `verified` or `unknown`. Keep a copy of what was public by cutoff; a later release does not count. Predefine success: at least 20 first-time, non-team buy wallets for this mint in minutes **(2,30]**. Ignore transfers, count each wallet once from decoded swaps, exclude declared wallets and run an alternative conservative cluster filter. Multiple wallets can still be one person. Optionally study day-7 retention and sellable paper returns separately; don't rename a price jump “buyers”.
3. Include silent, failed, unlisted and migrated launches. Follow trades across migration; if actual coverage stops, record `gap`, not zero. Record baseline venue, UTC date, **opening** depth band, pre-launch audience band, paid promotion known by cutoff and missingness. Do not match on later volume or price: those could be consequences of exposure. Freeze thresholds, split time periods, separate repeat creators and report comparability/selection bias.
4. Fill a **working copy** of the [blank cohort CSV](../../templates/study.csv) using the [study protocol](../../notes/study.md), then run the [calculator](../../tools/cohort.py) as `python tools/cohort.py FILE.csv`, replacing `FILE.csv` with your populated copy. Report numerator/denominator by group, matched percentage-point difference, relative lift only if baseline >0, and uncertainty. The script bootstraps UTC day blocks only with sufficient day/arm counts. Check sensitivity to creator clustering and regime. If coverage, overlap or precision is poor, return `INCONCLUSIVE`.
5. This estimates association, not what caused a person to buy. As a cleaner test of **discovery** on your own site, randomly vary placement of a truthful demo link (all risks/disclosures and access otherwise identical) and compare opt-in demo use. Do not run a misleading token-sale experiment. Code-project examples are proposals, not performance rankings.

**Output:** method, window, exclusions, observed groups, missing counts, uncertainty, held-out results, limitations and two clearly named metrics. Never translate “relative lift” into “percentage of buyers from GitHub”.
