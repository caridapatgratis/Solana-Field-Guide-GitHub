# Publish proof that a stranger can check
**Input:** Rehearsal packet, actual finalized creation transaction (not a predicted mint), approved public accounts, verified release **if a product is claimed**, risk disclosures and conflicts.

1. Fill a copy of the [issuer proof template](../../templates/launch-proof.json) with **observed** values and timestamps. Mark not-applicable controls with a reason. Never convert an unknown to “revoked” or “locked”. For each team/treasury allocation list the wallet, % of initial supply and unlock terms. For each fee identify who receives it. Mark curve LP custody `not applicable before migration`; link to actual program and vault. Do not count virtual reserves as money. Before claiming all balances can transfer, separate the mint freeze authority from the observed state and coverage of token accounts. See the [frozen-balance check](../../notes/technical-audit.md#1-a-frozen-balance-can-still-be-counted).
2. If claiming affiliation with software, the **original maintainer’s** site and pinned release must independently name this exact mainnet mint. The project's own wallet can attest to control of a project address; it does not prove a human's identity. If the upstream project disclaims affiliation, label a lawful derivative as unofficial; no upstream utility claims. For an unrelated repo, remove the claim.
3. Make one [canonical address card](../../templates/address-card.md): network, full mint, creation signature/slot, token program, launch venue, fees and a risk line. Publish the same facts on the site, in the repo if there is one, and in pinned official X/Telegram announcements. For a repo-backed project, publish your completed `launch-proof.json` at the **root of the project’s own repo**, not in the kit’s template folder. This is your public output, not a file supplied for a live project. Before sharing, run `python tools/proof.py launch-proof.json` from the kit root with your completed copy there (or pass its real path). The [proof linter](../../tools/proof.py) expects `state: published` and `network: mainnet-beta`; it checks the shape of selected fields, not truth, affiliation or safety. A blank or devnet draft should fail. Publish only after human approval.
4. Give early traders public, simultaneous access to the facts and the ordinary venue. Give longer-term users demos, release notes, bug reports, a treasury calendar and an incident contact. Disclose paid ads, market makers and sponsored channels. Never coordinate first-block purchases, fabricate demand, hide owned wallets or promise returns.
5. At launch, after migration, on authority/unlock changes, and weekly thereafter: compare chain vs manifest, timestamp a new hash-linked revision, update the public changelog and pin corrections. If mismatched, publish a warning; never silently edit history. Measure demo use and returning users as well as market quality.

**Output:** Manifest + an address card + a dated update/incident log. Use the [independent sign-off worksheet](../../templates/independent-signoff.md). The [independent scanner](../discover-mints/SKILL.md) starts from the transaction, not this file. A mismatch blocks the related claim.

**Kit location:** Run commands from the kit root, not this skill folder. See the [operator setup](../../README.md) and [agent routing map](../../AGENTS.md). `SOLANA_LAB_ROOT` is an optional agent convention; the Python tools do not read it.
